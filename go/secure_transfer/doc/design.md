# 设计

## 方案

使用椭圆曲线协商算法得到共享密钥，共享密钥派生得到最终加密密钥，使用对称加密算法加密

- 曲线与密钥协商协议：Curve25519 X25519
- 最终加密密钥派生算法：sha256
- 对称加密算法：aes-gcm 256
- 加密方式：
    - 文件大小 <10m：一次性读取到内存加密
    - 文件大小 >10m：流式加密

程序中同时保留一次性加密和流式加密两种加密方式，主要是考虑到：

1. 如果小文件也使用流式加密将导致：运行速度变慢、分配内存更多以及可能会产生中间文件（非首帧验证失败）
2. 流式加密可以进一步优化，导致流式加密的代码一眼看上去找不到重点，所以保留一次性加密的代码用作功能流程简述。流式加密优化方向：
    - 读文件、加密、写文件并发进行
    - 加密过程多goroutine并发执行
    - channel通信过程中的异常处理（阻塞、退出等）
    - 每一帧的加解密都会分配一些很快就会作废的大对象，使用缓冲池复用这些对象

## 加密文件编码规则

程序采用`技术准备-标准非对称加解密流程`小节中的流程，本节定义并详细介绍`哪些内容拼在密文前面`

```txt
header len + 'ST' + enc method + 
public key len + public key +
base nonce len + base nonce +
salt len + salt +
aad len + aad +
ciphertext
```

通常将解密要用到的参数编码到加密文件开头：

- 临时公钥：必填，用于解密期间协商共享秘钥
- 基础nonce：必填，加密时使用
    - 一次性加密：基础nonce后补0凑够位数
    - 流式加密：7 (base nonce) + 1 (末帧标识) + 4 (帧索引)
- 派生盐：选填，协商出的共享密钥已经足够随机，可以不用加盐进一步强化
- AAD：选填，目前选择将整个文件头除了aad的部分做一个hash (sha256)，当做AAD
- 其他可编码参数：派生算法 (sha256)、派生备注 (info)、加密算法 (aes-gcm 256)，均采用约定的方式，不编码进加密文件

编码规则：`文件头总长度+[参数1长度+参数1值]+[参数2长度+参数2值]+...`，文件头长度：95

- `header len`：整个文件头（一直到正文之前）的长度
    - 本工具中文件头 **有效**长度固定为94，即加密文件将固定以`^ST`开头
    - 94 = (2+1) + 4 + (16+7+32+32)
- `ST`：开头标记，项目名secure transfer的简写
- `enc method`：一次性读取到内存中加密/流式加密
- `public key`：X25519公钥，32 Bytes
- `base nonce`：基础nonce，7 Bytes
- `salt`：派生盐，16 Bytes
- `aad`：32 Bytes

流式加密密文（一帧）：

- 末帧标识：1 Byte
- 帧索引：4 Bytes
- 有效内容长度：4 Bytes
- 有效内容：x Byte (s)
